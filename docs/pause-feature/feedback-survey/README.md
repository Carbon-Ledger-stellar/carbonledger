# Pause Feature Feedback Survey

A survey of admin users on the design and usability of the emergency pause
on `carbon_credit` and `carbon_marketplace` (#1327).

| Step | Artifact |
|---|---|
| 1. Survey design (18 questions) | [survey.md](survey.md) (questionnaire) · [survey.json](survey.json) (definition + recommendation rules) |
| 2. Distribution to admin users | [distribution-plan.md](distribution-plan.md): invitees, tool setup, timeline, invitation template, privacy |
| 3. Results analysis | [`scripts/analyze_pause_survey.py`](../../../scripts/analyze_pause_survey.py): CSV export → statistics |
| 4. Feedback report | Generated by the script (`--out report.md`), then completed with themes as described in the distribution plan |
| 5. Improvement recommendations | Generated from the rules in `survey.json`, and compared with [baseline-recommendations.md](baseline-recommendations.md) (code-review findings) |

## Survey structure

| Section | Questions | Measures |
|---|---|---|
| About you | q1–q3 | Role (used to segment results), pause experience, training completed |
| Understanding and usability | q4–q10 | Blocked operations, choosing the window, 72 h limit, status visibility, error clarity, two-switch design, time to pause |
| Fit for incidents | q11–q13 | Sufficient control, known limitations, unexpected expiry |
| Tooling and training | q14–q16 | Preferred interface, training quality, recommendation score (0–10) |
| Open feedback | q17–q18 | Most confusing part, one change to make |

## Quick start

```bash
# After exporting responses (columns q1..q18) to responses.csv:
python3 scripts/analyze_pause_survey.py responses.csv --invited 12 --out pause-survey-report.md

# Tests
python3 -m unittest scripts/test_analyze_pause_survey.py
```

## Changing the survey

Edit `survey.json` and `survey.md` together, keeping question ids stable. The
test suite checks that both files contain the same questions and options, and
that every recommendation rule references a real question/option. For a new
run with changed questions, bump `id` / `version` in `survey.json` so results
from different versions aren't mixed.
